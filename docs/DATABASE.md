# Database Schema Documentation

## Overview

- Database: PostgreSQL
- ORM: TypeORM (with NestJS `@nestjs/typeorm`)
- Cache / shared state: Redis (see "Redis Keys" below)
- Naming conventions:
  - Tables: plural, snake_case (`users`, `leads`, `activities`, `refresh_tokens`)
  - Columns: snake_case (`created_at`, `dealership_id`); entity properties are camelCase and mapped with `@Column({ name })`
  - Primary keys: `uuid` (generated by the application or `gen_random_uuid()`)
  - Foreign keys: `<entity>_id` or a role name (`assignee_id`, `created_by`)
  - Timestamps: `timestamptz` (UTC)
  - Enums: stored as `varchar` + CHECK constraint (or native PostgreSQL enum), values UPPER_SNAKE_CASE
- Schema changes: TypeORM **migrations only** (`synchronize: false` in every environment)
- Multi-tenancy: `users` (except ADMIN) and `leads` carry `dealership_id`; `activities` inherit it through their lead. Every lead query filters by `dealership_id`

## Tables by Feature

### Dealership & User Management

#### dealerships table

| Column | Type | Constraints | Description     |
| ------ | ---- | ----------- | --------------- |
| id     | uuid | PK          | Dealership ID   |
| name   | text | NOT NULL    | Dealership name |

#### users table

| Column         | Type                                              | Constraints                  | Description                                                              |
| -------------- | ------------------------------------------------- | ---------------------------- | ------------------------------------------------------------------------ |
| id             | uuid                                              | PK                           | User ID                                                                  |
| dealership_id  | uuid                                              | FK → dealerships.id, nullable | Dealership the user works for; `NULL` only for `ADMIN`                   |
| full_name      | text                                              | NOT NULL                     | Full name                                                                |
| email          | text                                              | NOT NULL, UNIQUE             | Login email (stored in lowercase)                                        |
| password_hash  | text                                              | NOT NULL                     | bcrypt hash of the password                                              |
| role           | varchar (enum: `ADMIN`, `MANAGER`, `SALER`)       | NOT NULL                     | Access role                                                              |
| is_active      | boolean                                           | NOT NULL, default `true`     | `false` = account disabled (employee left)                               |
| deactivated_at | timestamptz                                       | nullable                     | When the account was disabled                                            |
| created_at     | timestamptz                                       | NOT NULL, default `now()`    | When the account was created                                             |

Constraint: `CHECK ((role = 'ADMIN' AND dealership_id IS NULL) OR (role <> 'ADMIN' AND dealership_id IS NOT NULL))`. A dealership can have many `MANAGER` users.

#### refresh_tokens table

One row per login (device). This replaces a single token column on `users` so one user can be signed in on several devices and each device can be revoked on its own.

| Column     | Type        | Constraints                         | Description                                                        |
| ---------- | ----------- | ----------------------------------- | ------------------------------------------------------------------ |
| id         | uuid        | PK                                  | Refresh token record ID                                            |
| user_id    | uuid        | FK → users.id, NOT NULL             | Owner                                                              |
| token_hash | text        | NOT NULL, UNIQUE                    | SHA-256 hash of the refresh token (the raw token is never stored)  |
| device_info | text       | nullable                            | `User-Agent` captured at login                                     |
| expires_at | timestamptz | NOT NULL                            | Expiry (7 days after issue)                                        |
| revoked_at | timestamptz | nullable                            | Set on logout, rotation or deactivation; `NULL` = still valid      |
| created_at | timestamptz | NOT NULL, default `now()`           | Issue time                                                         |

### Lead Management

#### leads table

| Column           | Type                                                           | Constraints                   | Description                                                              |
| ---------------- | -------------------------------------------------------------- | ----------------------------- | ------------------------------------------------------------------------ |
| id               | uuid                                                           | PK                            | Lead ID                                                                  |
| dealership_id    | uuid                                                           | FK → dealerships.id, NOT NULL | Owning dealership                                                        |
| assignee_id      | uuid                                                           | FK → users.id, nullable       | `SALER` in charge; `NULL` until a `MANAGER` assigns the lead             |
| full_name        | text                                                           | NOT NULL                      | Customer name                                                            |
| email            | text                                                           | nullable                      | Customer email                                                           |
| phone            | text                                                           | nullable                      | Customer phone                                                           |
| product_category | text                                                           | nullable                      | Group of goods the customer is interested in (e.g. vehicle, parts)       |
| product_name     | text                                                           | nullable                      | Specific goods the customer is interested in                             |
| message          | text                                                           | nullable                      | Free-text message from the customer                                      |
| source           | text                                                           | NOT NULL, default `WEBSITE`   | Where the lead came from                                                 |
| status           | varchar (enum: `NEW`, `CONTACTED`, `QUALIFIED`, `WON`, `LOST`) | NOT NULL, default `NEW`       | Lead lifecycle                                                           |
| idempotency_key  | text                                                           | nullable                      | Client-generated UUID v4 sent in `Idempotency-Key`                       |
| version          | integer                                                        | NOT NULL, default `1`         | Optimistic lock counter; every `UPDATE` on a lead increments it          |
| created_at       | timestamptz                                                    | NOT NULL, default `now()`     | Creation time                                                            |
| updated_at       | timestamptz                                                    | NOT NULL, default `now()`     | Last update time                                                         |

Constraint: `CHECK (email IS NOT NULL OR phone IS NOT NULL)` (a lead needs at least one way to contact the customer).

#### activities table (append-only)

| Column      | Type                                                       | Constraints               | Description                          |
| ----------- | ---------------------------------------------------------- | ------------------------- | ------------------------------------ |
| id          | uuid                                                       | PK                        | Activity ID                          |
| lead_id     | uuid                                                       | FK → leads.id, NOT NULL   | Lead the activity belongs to         |
| created_by  | uuid                                                       | FK → users.id, NOT NULL   | User who logged it                   |
| type        | varchar (enum: `CALL`, `EMAIL`, `SMS`, `MEETING`, `NOTE`)  | NOT NULL                  | Activity type                        |
| note        | text                                                       | nullable                  | Free-text note (required when `type = NOTE`, checked in the DTO) |
| occurred_at | timestamptz                                                | NOT NULL                  | When the follow-up actually happened |
| created_at  | timestamptz                                                | NOT NULL, default `now()` | When the row was recorded            |

Activities are never updated or deleted (audit history).

## Relationships

- dealerships 1:N users (ADMIN users have no dealership)
- dealerships 1:N leads
- leads 1:N activities
- users 1:N leads (`assignee_id`, optional)
- users 1:N activities (`created_by`)
- users 1:N refresh_tokens (one row per device)

## Indexes

### users

- `users_pkey` (PK)
- `UNIQUE (email)`

### refresh_tokens

| Index                | Purpose                                            |
| -------------------- | -------------------------------------------------- |
| `UNIQUE (token_hash)` | Look up the token on `/auth/refresh`              |
| `(user_id)`          | Revoke every token of a user (deactivate, reuse detected) |

### leads

| Index                                                                                            | Purpose                                 |
| ------------------------------------------------------------------------------------------------ | --------------------------------------- |
| `(dealership_id, created_at DESC, id DESC)`                                                      | Cursor pagination for the MANAGER inbox |
| `(dealership_id, assignee_id, created_at DESC, id DESC)`                                         | Cursor pagination for the SALER inbox   |
| `(dealership_id, status, created_at DESC)`                                                       | Filter by status                        |
| `UNIQUE (dealership_id, idempotency_key) WHERE idempotency_key IS NOT NULL` (partial, migration) | Prevent duplicate leads on client retry |
| `(dealership_id, lower(email))`                                                                  | Search leads by email                   |

### activities

| Index                                  | Purpose            |
| -------------------------------------- | ------------------ |
| `(lead_id, occurred_at DESC, id DESC)` | Fast timeline read |

## TypeORM Entity Details

### User entity (src/users/entities/user.entity.ts)

```typescript
import { Column, CreateDateColumn, Entity, PrimaryGeneratedColumn } from 'typeorm';
import { Role } from 'src/common/enums';

@Entity('users')
export class User {
  @PrimaryGeneratedColumn('uuid')
  id: string;

  // NULL only for ADMIN (enforced by a CHECK constraint in the migration)
  @Column({ name: 'dealership_id', type: 'uuid', nullable: true })
  dealershipId: string | null;

  @Column({ name: 'full_name' })
  fullName: string;

  @Column({ unique: true })
  email: string;

  @Column({ name: 'password_hash' })
  passwordHash: string;

  @Column({ type: 'varchar' })
  role: Role;

  @Column({ name: 'is_active', default: true })
  isActive: boolean;

  @Column({ name: 'deactivated_at', type: 'timestamptz', nullable: true })
  deactivatedAt: Date | null;

  @CreateDateColumn({ name: 'created_at', type: 'timestamptz' })
  createdAt: Date;
}
```

### Lead entity (src/leads/entities/lead.entity.ts)

```typescript
import {
  Column, CreateDateColumn, Entity, Index, OneToMany,
  PrimaryGeneratedColumn, UpdateDateColumn, VersionColumn,
} from 'typeorm';
import { LeadStatus } from 'src/common/enums';
import { Activity } from './activity.entity';

@Entity('leads')
@Index('idx_leads_inbox', ['dealershipId', 'createdAt', 'id'])
@Index('idx_leads_assignee_inbox', ['dealershipId', 'assigneeId', 'createdAt', 'id'])
@Index('idx_leads_status', ['dealershipId', 'status', 'createdAt'])
@Index('uq_leads_idempotency', ['dealershipId', 'idempotencyKey'], {
  unique: true,
  where: '"idempotency_key" IS NOT NULL',
})
export class Lead {
  @PrimaryGeneratedColumn('uuid')
  id: string;

  @Column({ name: 'dealership_id', type: 'uuid' })
  dealershipId: string;

  @Column({ name: 'assignee_id', type: 'uuid', nullable: true })
  assigneeId: string | null;

  @Column({ name: 'full_name' })
  fullName: string;

  @Column({ type: 'text', nullable: true })
  email: string | null;

  @Column({ type: 'text', nullable: true })
  phone: string | null;

  @Column({ name: 'product_category', type: 'text', nullable: true })
  productCategory: string | null;

  @Column({ name: 'product_name', type: 'text', nullable: true })
  productName: string | null;

  @Column({ type: 'text', nullable: true })
  message: string | null;

  @Column({ default: 'WEBSITE' })
  source: string;

  @Column({ type: 'varchar', default: LeadStatus.NEW })
  status: LeadStatus;

  @Column({ name: 'idempotency_key', type: 'text', nullable: true })
  idempotencyKey: string | null;

  // Every UPDATE on leads must also run `version = version + 1`
  // (QueryBuilder updates do not bump @VersionColumn automatically).
  @VersionColumn()
  version: number;

  @CreateDateColumn({ name: 'created_at', type: 'timestamptz' })
  createdAt: Date;

  @UpdateDateColumn({ name: 'updated_at', type: 'timestamptz' })
  updatedAt: Date;

  @OneToMany(() => Activity, (activity) => activity.lead)
  activities: Activity[];
}
```

## Redis Keys

| Key                                         | Value / TTL                                                            | Purpose                                                              |
| ------------------------------------------- | ---------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `bl:jti:{jti}`                              | `1`, TTL = remaining life of the access token                          | Blacklist of a single revoked access token (logout)                  |
| `bl:user:{userId}`                          | revocation timestamp, TTL = access token lifetime (15 min)             | Reject every token issued before the user was deactivated            |
| `lead:{dealershipId}:{leadId}`              | JSON lead (includes `assigneeId` and `version`), TTL ~5 min            | Cache for `GET /leads/{id}`                                          |
| `lead:{dealershipId}:{leadId}:activities`   | JSON `{ assigneeId, items[20] }` for the default page, TTL ~5 min      | Cache for `GET /leads/{id}/activities` with `offset=0&limit=20&order=desc` only |
| throttler counters                          | managed by `@nestjs/throttler` Redis storage                           | Distributed rate limiting                                            |

PostgreSQL is always the source of truth; Redis data can be lost without losing business data (Redis runs as a single instance).

Cache rules:

- Only the default activity page is cached. Other `offset`, `limit` or `order` values read PostgreSQL directly, so a new activity never has to invalidate many keys.
- Both cache entries store `assigneeId`, so the SALER scope check (`assigneeId = userId`) also runs on a cache hit; a miss in scope returns `404`.
- Cache is written only after COMMIT. If a cache write fails, log a warning and `DEL` the key.

## Data Flow & Usage Patterns

1. **Lead ingest**: website calls `POST /leads` with `X-API-Key` and optional `Idempotency-Key`. The service looks up an existing lead by `(dealership_id, idempotency_key)`; found → return it (`200`), not found → `INSERT` with `status = 'NEW'` (`201`). The partial unique index is the final guard against races. No key → always a new lead; there is no dedup by name or email.
2. **Lead inbox**: keyset (cursor) pagination on `(created_at, id)`, always filtered by `dealership_id`. MANAGER sees all leads of the dealership (including `assignee_id IS NULL`); SALER also filters `assignee_id = userId`.
3. **Lead detail** (the UI calls two APIs):
   - `GET /leads/{id}`: Redis lookup first; on a miss read the lead (filtered by `dealership_id`) and fill the cache. `404` is never cached.
   - `GET /leads/{id}/activities`: for the default page, Redis lookup first; on a miss check the lead is in scope, read the page with `LIMIT ? OFFSET ?` and fill the cache.
4. **Add activity**: one transaction: `INSERT activity` + conditional `UPDATE leads SET status = 'CONTACTED', version = version + 1 WHERE id = ? AND status = 'NEW'`. After COMMIT, re-read the lead and the default activity page and rebuild both cache entries.
5. **Manual lead update**: `PATCH /leads/{id}` carries `version`: `UPDATE leads SET ..., version = version + 1 WHERE id = ? AND dealership_id = ? AND version = ?`. No row affected → `404` (lead missing) or `409` (modified by someone else). After a successful update delete the lead cache key (and the activities key when `assignee_id` changed).
6. **Authentication**: login inserts a `refresh_tokens` row (hash only). Refresh revokes the old row and inserts a new one (rotation); presenting an already revoked token revokes every token of that user.
7. **Token revocation**: logout sets `revoked_at` on that device's row and blacklists the access token (`bl:jti:{jti}`). Deactivating an employee sets `is_active = false` and `deactivated_at`, sets `revoked_at` on all of the user's rows and writes `bl:user:{userId}`.

## Security

- Passwords: bcrypt hashes (`password_hash`), never plain text
- Refresh tokens: stored as **SHA-256** hashes in `refresh_tokens` (bcrypt is unsuitable: 72-byte input limit and JWTs share the same header prefix)
- Customer PII (email, phone, message) and activity `note` are never written to logs
- Every lead query is scoped by `dealership_id` taken from the authenticated user or API key, never from client input; SALER is also scoped by `assignee_id`
